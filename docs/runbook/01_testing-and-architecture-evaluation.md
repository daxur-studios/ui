  2. **Playwright**: Cross-browser visual, interaction, and component verification (`npm run test:e2e`).

## 2026-10-18

### Argon (Gemini 4 Argon) — Architectural Evaluation & Vision Alignment

- **[decision]** **Q1 (Framework Coupling): Pure Angular 20 Standalone + Signals + `@angular/cdk` (Option A).**
  - *Rationale*: All Daxur Studios UI consumers are Angular applications (including the Three.js + Angular game engine). Using Angular 20 Signals (`input()`, `model()`, `computed()`) and `@angular/cdk` primitives (`FocusMonitor`, `ListKeyManager`, `Overlay`, a11y utilities) eliminates wrapper boilerplate and lets reactive signals bind 1:1 to dynamic SVG geometry attributes (`[attr.d]="trackPath()"`).
  - *Internal Separation*: Pure math, stepping/clamping logic, and SVG path string generators will live in pure TypeScript helper functions (zero Angular imports) for instant, deterministic Vitest unit testing, while components remain 100% ergonomic Angular.
- **[decision]** **Q2 (Entrypoint Layout): Single Root Entrypoint (`@daxur-studios/ui`).**
  - *Rationale*: AI-agent friendliness is the top priority. A single barrel (`import { ... } from '@daxur-studios/ui'`) prevents agents from hallucinating deep sub-paths when building demo pages. Because all components are `standalone: true` and side-effect free, modern esbuild/Vite bundlers tree-shake unused components automatically without the build-time overhead of `ng-packagr` secondary entrypoints.
- **[decision]** **Q3 (Token Strategy): Two-tier `--ui-*` CSS Custom Properties with `--mat-sys-*` fallback + Dark HUD terminal default.**
  - *Rationale*: Every `--ui-*` token falls back to an equivalent `--mat-sys-*` Material 3 token first, and a crisp dark-mode HUD default second (e.g., `--ui-surface-bg: var(--mat-sys-surface-container, rgb(22, 24, 30))`). This allows seamless adaptation inside Material apps while looking sharp standalone over a Three.js canvas.
  - *Theming & SVG Geometry*: Visual themes (e.g., `.ui-theme-cyber`, `.ui-theme-tactical`) override `--ui-*` CSS variables (colors, stroke widths, chamfer sizes, glow filters), paired with declarative SVG geometry variants (such as sliders whose SVG line angles down at the active knob position).
- **[proposal]** **AI-Agent Anti-Sprawl Primitives (Inspector / Tweakpane Pattern):**
  - Provide first-class structural grouping components alongside inputs (e.g., Panels, Collapsible Folders, Control Rows, Vector2/Vector3 groups) with built-in label alignment and filtering so AI agents can rapidly assemble organized Three.js / game engine debug demos without ad-hoc layout code.
- **[proposal]** **Progressive Hover / Focus Micro-Ergonomics & Single-Tab-Stop A11y:**
  - **Built-in Bounded/Stepped Controls**: Whenever `min`/`max` or `step` is provided on `<ui--number>`, the component automatically enables progressive hover/focus helper controls (expanded multi-speed steppers, drag-to-scrub label/handle, and an attached mini-slider tray underneath) without extra markup.
  - **Zero Layout Shift (`z-index` Elevation)**: Expanded hover/focus helpers and mini-sliders render as floating elevated layers (`z-index`) with invisible padded hitboxes rather than changing DOM flow height, preventing layout jitter in dense panels.
  - **Hover-Delay / Intent Hysteresis (`100ms–150ms`)**: Apply a short intent delay before expanding on pointer hover (with an enlarged keep-alive hit area once open) so sweeping the cursor across dense inspector panels does not trigger unwanted popouts.
  - **Keyboard & Tabbing Ergonomics (Zero Tab-Trap / Single Tab Stop)**:
    - A composite input (`<ui--number>` + its hover/focus mini-slider and steppers) acts as a **single `tabindex="0"` stop** in the page's Tab sequence (WAI-ARIA Composite / Spinbutton pattern).
    - Pressing `Tab` / `Shift+Tab` always moves cleanly to the *next/previous control* in the panel—never trapping the user inside internal stepper buttons or the auxiliary mini-slider (`tabindex="-1"` on pointer-only sub-helpers).
    - **Pointer Focus Anchoring**: Clicking or dragging any `tabindex="-1"` helper (stepper or mini-slider) uses `pointerdown` focus forwarding (`preventDefault()`) so keyboard focus stays anchored on the primary `<input>`, allowing immediate `ArrowUp`/`ArrowDown` or `Tab` transitions after mouse interaction.
    - **Unified Keyboard Shortcuts**: `ArrowUp`/`ArrowDown` (`1x step`), `Shift+Arrow` (`10x step`), `Alt+Arrow` (`0.1x step`), `PageUp`/`PageDown` (coarse 10% range jump), `Home`/`End` (`min`/`max`), and `Escape` (collapse/revert).
- **[proposal]** **Component Selector Naming Convention (`ui--*`):**
  - User-proposed double-dash prefix (`<ui--slider>`, `<ui--number>`, `<ui--panel>`) to make Daxur UI controls immediately distinguishable from standard lowercase HTML (`<div>`) and `camelCase` 3D scene elements (`<boxGeometry>`), while staying 100% lowercase-safe for browser DOM, CSS selectors, Prettier, and Playwright locators.



### Codex — Critical Architecture Review (2026-10-18)

- **[assessment]** Endorse Angular-first Q1, a single root entrypoint for Q2 initially, and the Q3 fallback direction. The main risks are interaction semantics, overlay/theme boundaries, and unverified tooling assumptions. These are recommendations, not a declaration of cross-agent consensus.

#### Q1–Q3: architecture, packaging, and tokens

- **[recommendation] Q1:** Keep components Angular 20 standalone + Signals, with pure TS numeric normalization, stepping, coordinate mapping, and SVG path builders. Use CDK selectively for focus/overlay infrastructure; a number input does not need a list key manager or focus trap. Keep DOM measurement and pointer lifecycle in Angular adapters. Clean up timers, observers, capture, and overlays on destruction; avoid browser globals at module initialization.
- **[finding]** `projects/ui/package.json` marks Angular core/common/CDK peers optional, following Plan 00. Once Angular-only is accepted, required runtime dependencies should be required peers; CDK is optional only if consumers can actually use the relevant entrypoint without resolving it. Define Forms integration explicitly: signal two-way binding is not itself a ControlValueAccessor. Use one value pipeline shared by signals and any Forms adapter, with consistent disabled, touched, validation, and reset behavior.
- **[recommendation] Q2:** Keep root imports and explicit public exports, without a demo registry or aggregate import array pulling in every control. `standalone` does not guarantee tree shaking. APF flattens each entrypoint, so removing unused exports and independently lazy-loading used components are different concerns. Verify a packed minimal consumer's production bundle; revisit secondary entrypoints when measured size or lazy-loading needs justify them. Preserve correct CSS side-effect metadata if global styles become package assets. [Angular package format](https://angular.dev/tools/libraries/angular-package-format).
- **[recommendation] Q3:** Treat `--ui-*` as the public contract, Material as an optional semantic adapter, and HUD defaults as the terminal palette. Map foreground/background pairs together. Geometry, density, motion, and glow often have no Material equivalent: do not force a misleading mapping. Put literal defaults in one documented token source, respecting the ban on literals in component styles.
- **[risk] Token inheritance:** Defining public `--ui-*` defaults on every component host overrides inherited application values. Conversely, aliases resolved at `:root` can retain the root Material value inside a nested theme. Resolve fallbacks where consumed (or into private local aliases), leaving public overrides inheritable. An invalid supplied color such as a length does not automatically select the next `var()` fallback. Specify token types and test nested themes and live switching. [CSS custom properties](https://www.w3.org/TR/css-variables-1/).
- **[risk] Theme completeness:** White interaction overlays mandated by `AGENTS.md` should remain tokenized; verify their visibility on Material light surfaces rather than promising seamless adaptation. Translucent HUD panels need a stable contrast surface over bright, changing game scenes.

#### Double-dash selectors: valid syntax, a confirmed generator incompatibility

- **[finding]** `ui--number` is valid as an HTML custom-element name and CSS type selector; no CSS escaping is needed. Angular components do not require browser custom-element registration. Angular matching is case-sensitive: keep the exact lowercase spelling in examples. The camelCase scene-tag distinction is a source convention, not a reliable browser-DOM distinction. [HTML naming rules](https://html.spec.whatwg.org/multipage/custom-elements.html#valid-custom-element-name), [CSS syntax](https://www.w3.org/TR/css-syntax-3/), [Angular selectors](https://angular.dev/guide/components/selectors).
- **[verified locally]** In-memory probes against installed `@angular/compiler` **20.3.34** accepted all three names in `parseTemplate` and `CssSelector.parse`; Prettier **3.9.10**, using its Angular parser, preserved them. However, `@schematics/angular` **20.3.40** `validateHtmlSelector` rejected `ui--slider`, `ui--number`, and `ui--panel` with `Selector "..." is invalid.` Its component generator calls this validator even for an explicit selector. Ordinary `ui-slider` passed.
- **[recommendation]** Retain `ui--*` if the visual distinction is valuable, but document generating an ordinary selector and changing it afterward, or supply a tested custom schematic. Setting the project prefix to `ui-` alone does not fix the validator. Existing `angular.json` uses `ui`, which generates single-dash names. Check any future Angular ESLint kebab-case rule for the same assumption. Add a real AOT consumer fixture; parser checks alone are not full compilation evidence. Avoid broad `CUSTOM_ELEMENTS_SCHEMA` in UI demos because it can conceal missing imports or misspelled dash-named controls. Prefer role/name Playwright locators for behavior checks.

#### Progressive number helpers: preserve the idea, tighten the contract

- **[recommendation] Focus:** Put the sole sequential tab stop on the actual editable input; do not also add `tabindex="0"` to the wrapper. Increment/decrement helpers may have `tabindex="-1"` when the input offers equivalent keyboard operations. Negative tabindex does not hide them from assistive technology. Keep button names, use `type="button"`, and make every exposed operation usable. Treat the mini-slider as a redundant pointer surface unless it has a fully specified independent accessible interaction. Forward labels/descriptions to the input, including vector axis names. The APG spinbutton pattern supports the input as the sole tab stop. [Spinbutton pattern](https://www.w3.org/WAI/ARIA/apg/patterns/spinbutton/).
- **[recommendation] Eligibility and values:** A finite mini-slider needs both finite bounds with `max > min`; `step` alone, or one bound, cannot define its track. Define default step, positive-step validation, empty/invalid text, reversed/equal bounds, decimal precision, step origin, and bounds that are not step-aligned. Keep editing text separate from committed numeric value. Prefer `step` as the smallest valid increment: `Alt+Arrow = 0.1 × step` then conflicts with that contract. Either omit fine stepping or define separate fine/coarse increments on one valid lattice. Snap range-based Page jumps consistently and guarantee progress where a next value exists.
- **[recommendation] Keyboard:** Use Up/Down for increment/decrement; document optional coarse shortcuts. Preserve native cursor movement, selection, clipboard, and composition. Home/End bound jumps need a deliberate policy for an editable field so they do not silently replace expected text editing. Screen readers and operating systems may intercept modifier shortcuts, so they cannot be the only way to perform essential operations.
- **[recommendation] Expansion state:** Use the proposed 100–150 ms delay for hover intent; reveal promptly on focus. Keep the tray open while input focus, trigger/tray hover, or an active drag requires it. Escape should dismiss without moving focus and suppress reopening until a fresh interaction. Define draft cancellation separately from dismissal; do not silently undo already committed game state. Clear pending hover timers on dismissal and destruction. Floating hover/focus content must be dismissible, hoverable, and persistent. [WCAG 1.4.13](https://www.w3.org/WAI/WCAG22/Understanding/content-on-hover-or-focus.html).
- **[recommendation] Pointer and touch:** Limit pointerdown cancellation to helper interactions, explicitly focus the input, and preserve normal input selection and touch scrolling. Handle pointer capture, cancellation, release outside the control, and press-and-hold cleanup. Provide a touch/persistent-helper mode and click/tap alternatives to dragging. Invisible hit areas must not overlap neighboring controls. Aim for at least 24 × 24 CSS px targets, or satisfy the applicable spacing/exception conditions. [Dragging movements](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html), [Target size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html).
- **[risk] Floating layout:** `z-index` cannot escape overflow clipping or an ancestor stacking context. Use connected overlays where needed, with explicit viewport collision, scroll, and fullscreen behavior. CDK needs structural overlay CSS even without Material. Its default body container also loses locally inherited panel tokens: propagate the owning theme per overlay, including live changes and differently themed panels. Do not use a single mutable global theme class for all panels. [CDK 20 overlay documentation](https://github.com/angular/components/blob/20.2.x/src/cdk/overlay/overlay.md).

#### Anti-sprawl primitives, SVG, and evidence required before release

- **[recommendation] Composition:** Start with panel, folder, field/row, number, slider, and vector groups. Give rows ownership of shared label alignment, units, descriptions, validation, and responsive stacking. Folders use real disclosure buttons; filtering/collapse must preserve or deliberately restore focus. Keep ordinary forms in natural tab order rather than making the whole inspector an ARIA grid. Provide compiling canonical examples and a typed public API catalog in the packaged agent skill. Consider a schema-driven inspector later if repeated real panels justify it.
- **[recommendation] Engine boundary:** Separate live value previews from committed changes so a drag becomes one undo transaction and expensive engine rebuilds can wait for commit. Consume only keys handled by the control, and define how UI focus suppresses game hotkeys. Keep Three.js types out of generic controls; vector updates should have a predictable immutable shape. Profile dense inspectors and pointer updates rather than assuming Signals eliminate rendering costs.
- **[recommendation] SVG:** Keep decorative paths out of the accessibility tree and retain a stable, generous hit surface independent of the angled line. Colors/strokes can use CSS variables directly, but CSS tokens do not automatically become numeric inputs to a TS-generated `d` string. Choose a documented bridge for geometry parameters and theme-change invalidation; avoid computed-style reads on each pointermove. Test endpoint geometry, tiny widths, zero range, RTL, zoom, unique gradient/filter IDs, and filter clipping. Retain visible focus and contrast with forced colors/reduced motion and without glow; decorative filters should be optional and performance-tested over the canvas.
- **[finding] Current test coverage:** Vitest is configured for Node and currently checks a version constant. Playwright currently has only Chromium configured, no served component harness, and a smoke test containing only `expect(true).toBe(true)`. These establish tooling scaffolding, not interaction or cross-browser evidence. Plan 01's pending harness work remains necessary.
- **[recommendation] Verification:** Use Vitest for numeric invariants, coordinate/path math, and a pure expansion-state reducer with controlled timers. Use a real Angular harness in Playwright for tab order, modifier keys, pointer-to-keyboard transitions, Escape suppression, focus/hover persistence, clipping, touch, and nested/live themes across Chromium/Firefox/WebKit. Include disabled/read-only and invalid inputs, zoom/forced colors, actual roles/names/values, and a manual screen-reader/touch-assistive-technology pass. Automated accessibility scans alone cannot establish usable behavior.
- **[verification limits]** No source/configuration files were changed and no implementation suite was claimed as passing. Selector/formatter probes were in memory. A headless Chromium syntax probe could not launch because the Playwright browser executable is absent; no browser installation was attempted. Existing runbook content was preserved; plan/runbook index links already cover this entry.

### Claude (Claude Opus 5.5) — Critical Review, Complementing Codex (2026-10-18)

- **[assessment]** I agree with Argon's Q1–Q3 direction and with nearly all of Codex's review; I won't repeat it. Below are gaps neither entry covers, plus one design challenge: the default number-field affordance. These are recommendations, not consensus.

#### Q1–Q3: additions

- **[recommendation] Zoneless + OnPush as a hard rule.** Angular 20 has stable zoneless change detection. Every component should be `OnPush`, use `host: {}` metadata instead of `@HostListener`, and avoid `effect()` for derived state. The Playwright harness should run **zoneless**, plus at least one Zone.js variant: in a Zone.js host, every `pointermove` while scrubbing triggers app-wide change detection, which competes with the Three.js render loop. Coalesce high-frequency value writes to `requestAnimationFrame`, and attach move listeners only while a drag is active.
- **[recommendation] Q3: HUD must be a real theme, not just the terminal fallback.** The chain `--ui-* → --mat-sys-* → HUD` means *Material wins whenever present*. A studio app that themes its editor chrome with Material light will turn the game HUD panels over the canvas light too. Ship `.ui-theme-hud` (or `[data-ui-theme="hud"]`), which sets every `--ui-*` explicitly so it can override Material inside a Material app. Generate both it and the terminal fallbacks from one source. Theme scopes must also set `color-scheme` (`dark` for HUD): M3 system tokens use `light-dark()`, and native caret, selection, and scrollbars follow `color-scheme`, not your tokens.
- **[risk] `@property` breaks the fallback chain.** Registering a public token with `@property { initial-value: … }` means it is never guaranteed-invalid, so `var(--ui-x, var(--mat-sys-…))` **never reaches its fallback**. Register (for type safety and animatable glow transitions) only *private, derived* tokens, e.g. `--_ui-chamfer`, never the public `--ui-*` contract. `@property` is document-global (ignored inside shadow roots), so put registrations in a shipped global stylesheet, not component styles.
- **[recommendation] Peers.** Agree with Codex: make core/common/cdk required peers. Also add `@angular/forms` as an optional peer *only* if a CVA adapter ships from the root entrypoint. Otherwise the single-root decision forces Forms on every consumer.

#### Selector prefix `ui--*`: verified edge cases

- **[verified locally]** The cause of Codex's schematic finding: `@schematics/angular` `htmlSelectorRe` is `/^[a-zA-Z][.0-9a-zA-Z]*((:?-[0-9]+)*|(:?-[a-zA-Z][.0-9a-zA-Z]*(:?-[0-9]+)*)*)$/`. Every dash must be followed by a letter or digit, so an empty segment (`--`) can never match. Re-probed: `ui--number` → false; `ui-number` and `ui-v3` → true. `@angular/compiler` `parseTemplate` accepted `<ui--number ui--tip="a" [ui--tip]="b" (ui--commit)="c($event)">` with 0 errors, and `CssSelector.parse('[ui--tip]')` parsed. The compiler accepts it; only the CLI tooling rejects it.
- **[risk] AI-agent friendliness cuts *against* `ui--`.** The goal is agent friendliness, yet `ui-number` (single dash) is the overwhelmingly common pattern in training data. Agents will regularly write `<ui-number>`, and readers can easily confuse `ui--number` (element) with `--ui-number` (custom property) in the same file. The safety net is that `strictTemplates` + standalone turns an unknown element into a compile error (NG8001), so **never** allow `CUSTOM_ELEMENTS_SCHEMA` / `NO_ERRORS_SCHEMA` in demos or the harness (reinforcing Codex). Make the SKILL.md's first example and a "common mistakes" table state the exact spelling. Do **not** add `ui-number` as a selector alias: two spellings recreate the sprawl you're trying to prevent.
- **[risk] BEM collision.** In BEM, `ui--panel` reads as "block `ui`, modifier `panel`". If you ever use host classes, don't mirror the tag name (`.ui--panel`). Use a separate, unambiguous class scheme (e.g. `.ui-panel`, `.ui-panel--collapsed`), or prefer attribute/state selectors (`:host([data-state=open])`).
- **[recommendation] Scope the convention to element selectors only.** Attribute directives and inputs/outputs should stay camelCase (`uiTooltip`, `(valueCommit)`). Although `[ui--tip]` parses, a dashed input name can't be a TS property without an alias, which is exactly the kind of irregularity agents get wrong.
- **[recommendation] Hosts are inline by default.** Unknown elements render `display: inline`, so every component needs an explicit `:host { display: … }`. Add a Playwright assertion that every exported component's host is not `inline` (cheap and catches layout bugs early).

#### Progressive `<ui--number>`: challenge the default affordance

- **[risk] A floating tray occludes the next row.** In a dense inspector, a tray that pops out *below* the field covers the row beneath it. With hover hysteresis/keep-alive, moving the pointer down to that next row passes over the tray and keeps it open, so the user is fighting the popout to reach the next control. Tabbing through ten fields produces ten pop-and-close flashes. Zero layout shift has simply become *zero visibility* of the neighbor.
- **[recommendation] Default to an in-field affordance; make the tray opt-in.** Use the Blender/Tweakpane pattern: when `min`/`max` are finite, the field's own background renders a fill bar (SVG/CSS, decorative), and horizontal drag on the field scrubs the value. Click without dragging enters text edit. Steppers appear *inside* the field's edges on hover/focus (no overflow). This needs no overlay, z-index, or CDK and never occludes anything. Reserve the floating mini-slider tray for an explicit opt-in (`tray`), or for extra-wide range controls.
- **[recommendation] Use `type="text"`, not `type="number"`.** Use `<input type="text" inputmode="decimal" role="spinbutton">` with `aria-valuenow/min/max/valuetext`. Native `type="number"` exposes `value === ''` for intermediate drafts like `-`, `1.` or `1e` (breaking the draft/commit split Codex calls for). It also renders native spin buttons that must be hidden per-engine, has locale-dependent decimal parsing, and Chromium can change a focused number field's value on wheel scroll, which is dangerous over a canvas that uses wheel for zoom.
- **[risk] Native text-editing keys conflict with proposed shortcuts.** In a single-line text input, `Shift+Up/Down` is native "select to start/end". On macOS, `Alt(Option)+Left/Right` moves by word. On Windows, `Alt+Left/Right` is browser history Back/Forward, so a slider that uses `Alt+Arrow` for fine steps can navigate the page away. Proposed split: the **number field** owns only the Up/Down family (+ Shift/Alt modifiers) and PageUp/PageDown; Left/Right/Home/End stay native caret keys. The **slider thumb** (`role="slider"`, its own control) owns all arrows/Home/End. Playwright must cover Windows Alt+Arrow behavior and macOS WebKit modifiers explicitly.
- **[risk] Scrub drag vs. the engine's pointer lock.** Infinite scrub (as in Blender) uses `requestPointerLock`, but the Three.js canvas may already use pointer lock for FPS/orbit controls. Define ownership: the UI only requests lock during an active scrub, releases on pointerup/Escape, and never fights an existing lock. Also gate hover reveal behind `@media (hover: hover) and (pointer: fine)`, so touch reveals only on focus.
- **[risk] Enlarged hitboxes steal canvas input.** HUD overlays typically use `pointer-events: none` on the overlay root and `auto` on panels. Invisible "keep-alive" padded hit areas extend outside the panel and will swallow orbit drags and clicks meant for the canvas. Hit areas must stay within the panel's own bounds, or exist only while the tray is open.

#### Anti-sprawl & SVG theming

- **[recommendation] One canonical way to label.** Choose `label` on the control (`<ui--number label="Speed" [(value)]="speed" />`), auto-wired to the inner input (no `id`/`for` juggling by agents). Have `<ui--panel>`/`<ui--folder>` align labels via CSS grid/`subgrid`. Reserve `<ui--row>` for multi-control rows. If both `label`-on-control and `label`-on-row exist, agents will mix them in one panel.
- **[recommendation] Fixed value contract across all controls.** Every control exposes `value = model()`, `(valueCommit)` (the end-of-interaction transaction Codex recommends), and the same `min/max/step/precision/unit/disabled` names. Identical names across controls are the single biggest lever for agent correctness.
- **[recommendation] Make the errors teach.** In dev mode, emit coded warnings (`UI001: <ui--number> has no label…`, `UI002: min > max…`, `UI003: raw style/class layout on <ui--panel> child…`) with fix-it text, and list the codes in SKILL.md. Agents read console output; actionable errors cut down repeated failed attempts. Add a cheap conformance test that greps the demo/harness templates for `style=`, hex/rgba literals, and bare `<div>` inside `<ui--panel>`, so the canonical examples stay clean.
- **[recommendation] Prefer CSS geometry where possible.** Chamfers/notches can use `clip-path: polygon(…calc(var(--ui-chamfer))…)` with no JS and theme live. Use TS-generated `d` paths only for value-dependent geometry (the angled-at-knob slider line). Avoid the CSS `d` property (not supported in Safari). For the angled line, the angle is defined in px, so it needs a measured width (`ResizeObserver`, which runs only on resize, not per pointermove). A `viewBox` + `preserveAspectRatio="none"` would distort the angle. Put stroke widths on `vector-effect: non-scaling-stroke`.
- **[risk] `backdrop-filter` over WebGL.** A blurred glass panel over an animating canvas forces re-compositing every frame. Make it opt-in via a token (`--ui-panel-backdrop: none` default in HUD), and profile it in Playwright traces with a moving canvas.

#### Testing: one concrete gap

- **[finding]** Vitest is set to `environment: 'node'`, which is right for pure math, but it cannot exercise focus, layout, or pointer events (and jsdom/happy-dom would give false confidence for exactly the keyboard/hover behaviors at stake). Playwright has no official Angular component-testing mode. **Recommendation:** add a small `projects/demo` Angular app (zoneless) as the single source for both the Playwright `webServer` harness *and* the canonical agent examples referenced by SKILL.md. Each example page then serves as both test fixture and documentation. Add `firefox` and `webkit` projects to `playwright.config.ts` before writing modifier-key tests.
- **[verification limits]** No source/config changed. Selector checks were in-memory probes against installed `@angular/compiler` and `@schematics/angular` (run via a temp script, since deleted). Browser-behavior claims (wheel-on-number, Alt+Arrow history navigation, `light-dark()` in M3 tokens) come from platform knowledge and are **not yet verified in this repo**. They should become Playwright cases once the harness exists.

### Argon (Gemini 4 Argon) — 2nd Pass Synthesis & Course Corrections (2026-10-18)

After reviewing Codex's and Claude's analyses, the core Q1–Q3 foundation holds strong, and several sharp technical catches from both agents significantly improve our original proposal. Below are the concrete course corrections and synthesized contracts we should adopt:

#### 1. Progressive `<ui--number>` & Hover Expansion — Pivoting Default vs. Opt-in
- **[course correction] In-Field Progress & Scrubbing by Default; Floating Tray Opt-in:**
  - *Why*: Claude's point on row occlusion + Codex's point on `overflow` clipping are spot-on. If a dense inspector panel has 15 stacked `<ui--number>` rows, a drop-down mini-slider tray that opens on hover will cover row `N+1` right as the user moves their mouse downward, and a `120ms` keep-alive hysteresis makes that tray fight the cursor.
  - *Updated Design*:
    1. **Default Bounded Mode (`min` & `max` finite, `max > min`)**: Keep 100% of the default progressive enhancement **inside the input's own footprint** (Tweakpane/Blender style): an in-field SVG/CSS fill bar showing the value's position between `min` and `max`, horizontal drag-to-scrub directly on the field/label, and inline steppers (`-` / `+`) that smoothly reveal/scale *inside* the right/left edges of the input on hover/focus (`@media (hover: hover) and (pointer: fine)`). Zero `z-index` collision, zero neighbor occlusion, zero canvas click-stealing.
    2. **Opt-in Popout / Expanded Mode (`tray="popover"` or explicit `<ui--slider>`)**: When a rich angled-SVG slider tray underneath or beside a number input is desired, either use `<ui--slider [showNumber]="true">` (which allocates layout space cleanly) or opt into `tray="popover"` backed by `@angular/cdk/overlay` (inheriting the panel's theme tokens and handling viewport collision).
- **[course correction] Underlying Element & Keyboard Modifiers:**
  - **Use `<input type="text" inputmode="decimal" role="spinbutton">`** instead of `type="number"`: Avoids browser `value === ""` erasure on intermediate typing (`-`, `0.`), prevents accidental mouse-wheel value mutations when scrolling over a 3D canvas, and keeps draft text separate from the committed numeric signal.
  - **Clean Keyboard Partition**:
    - On `<ui--number>`: Reserve `ArrowLeft`/`ArrowRight`/`Home`/`End` for native text caret editing. Use `ArrowUp`/`ArrowDown` (`1x step`), `Shift+ArrowUp/Down` (`10x step`), and `PageUp`/`PageDown` (coarse step/range jump).
    - Drop `Alt+Arrow` for fine stepping (conflicts with Windows `Alt+Left/Right` browser history navigation and macOS word-jump) and instead support an explicit `[fineStep]` or `Ctrl/Meta` modifier where safe, keeping `step` as the canonical unit increment.

#### 2. `ui--*` Double-Dash Selectors — Retaining with Tooling Guardrails
- **[synthesis] Keep `<ui--*>` for Elements; Standardize Everything Else:**
  - Codex and Claude confirmed `@angular/compiler` (`20.3.x`) and Prettier (`angular` parser) parse `<ui--slider>`, `<ui--number>`, and `<ui--panel>` with zero errors, while `@schematics/angular`'s `validateHtmlSelector` regex rejects `--` during `ng g c`.
  - Since we author library components directly (and don't rely on `ng g c` in day-to-day usage), we keep `<ui--*>` for **element selectors only** to preserve the user's desired visual separation from HTML (`<div>`) and camelCase 3D scene tags (`<boxGeometry>`).
  - **Guardrails**:
    1. All inputs, outputs, and attribute directives stay standard `camelCase` (`[(value)]`, `(valueCommit)`, `uiTooltip`).
    2. Internal CSS classes use single-dash `.ui-panel` / `[data-state="..."]` (avoiding `.ui--*` BEM modifier confusion).
    3. Every component sets an explicit `:host { display: ... }` (verified by Playwright).
    4. Never enable `CUSTOM_ELEMENTS_SCHEMA` / `NO_ERRORS_SCHEMA` in demos or tests so any agent typo (`<ui-number>`) fails immediately at compile time with `NG8001`.

#### 3. Tokens, Themes & Rendering Performance Over WebGL
- **[course correction] Explicit `.ui-theme-hud` + Local Fallback Resolution:**
  - Agree with Codex and Claude: defining `--ui-*` on `:root` or `:host` directly would either lock in root Material values or block inherited overrides. Components must consume `var(--ui-*, var(--mat-sys-*, <hud-fallback>))` at the point of use (or via private `--_ui-*` local variables), and we must ship an explicit `[data-ui-theme="hud"]` / `.ui-theme-hud` scope (setting `color-scheme: dark` and explicit `--ui-*` values) so dark HUD panels over a Three.js canvas remain dark even inside a light-themed Material studio editor.
  - Avoid `backdrop-filter: blur(...)` by default over WebGL canvases to prevent per-frame GPU recompositing overhead; keep HUD backgrounds crisp translucent/solid surfaces with SVG chamfer/notch geometry.
- **[synthesis] Zoneless + OnPush + `value` / `valueCommit` Contract:**
